# Manchester Stock Exchange (MSEG)

## Introduction

The Manchester Stock Exchange (MSEG) system has been developed as a stock market management platform that handles company applications, stock listings, and trading operations. The implementation of this project was conducted by building a modular architecture where different parts of the system handle specific responsibilities. This includes separate modules for user authentication, database operations, user interface components, and the core business logic that runs the application.

During development, the focus was on creating a system that could scale effectively while remaining easy to maintain and providing a good user experience. The system works through a dual portal approach where stock exchange managers have access to different features compared to registered companies. This is managed through role-based access control which makes sure users can only access what they are supposed to. The manager portal lets stock exchange staff review and either approve or reject company listing applications. On the other hand, the company portal gives businesses the ability to submit their applications and track how their stocks are performing once they get listed. The stock market component displays stock prices visually and keeps track of historical data going back 366 days. This historical data uses a random walk pricing model to simulate realistic price movements over time.

Throughout the implementation process, several key requirements needed to be met. These included building a secure authentication system so only authorized users could access the platform, making sure database operations were efficient and maintained data integrity through proper relationships between tables, creating a responsive graphical interface that supports both light and dark themes, and ensuring comprehensive test coverage which has been documented in the TEST_PLAN.md file.

## 5. System Requirements

### 5.1 Software Requirements

For this project, Python was chosen as the main programming language and SQLite3 as the database system. The decision to use Python came from several practical reasons. Python allows for quick development because it has a large standard library that provides many built-in functions, which means less code needs to be written from scratch. It also works really well with Tkinter, which is the GUI framework used to build the visual interface of MSEG. Another advantage of Python is that the code is quite simple to read and understand, which makes it easier to implement complex business logic while keeping the codebase maintainable in the long run.

When it came to choosing a database, SQLite3 made the most sense for this application. Unlike other database systems that need separate server installations and configuration, SQLite3 is embedded directly into the application and requires no setup at all. It works without needing a separate database server running in the background, and it integrates smoothly with Python since it is already included in Python's standard library. This makes MSEG much simpler to deploy because there is no need to worry about external database dependencies. The setup process becomes straightforward, and this works well for both development and production use. Using an embedded database also removes any network delays that would happen if the database was on a separate server, which helps with performance.

Both Python and SQLite3 can be used with most popular development environments. This includes IDEs like PyCharm, Visual Studio Code, Sublime Text, and IDLE. This compatibility gives flexibility in terms of where and how the code can be developed and edited. The technologies chosen are also lightweight, which means the MSEG system can be easily moved between different computers and platforms without much hassle. Setting up the application on a new machine is quite simple and does not require complicated configuration steps.

### 5.2 Hardware Requirements

In terms of hardware and operating system requirements, MSEG has been designed to work across different platforms without needing high-end specifications. The application is compatible with Windows 10 or any later version, macOS version 10.14 or above, and Linux distributions such as Ubuntu 18.04 or higher, Fedora 30 or newer, or other equivalent Linux systems. The minimum hardware needed to run the system includes 2GB of RAM, at least 100MB of available disk space for the application and its data, and a display that supports a minimum resolution of 1280x720 pixels to ensure the interface displays properly.
